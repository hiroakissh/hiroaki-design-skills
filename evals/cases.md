# 代表的な依頼と確認観点

これらはスキルの選択と判断を確認するためのケース。実際に適用した結果と確認内容は `samples/*/review.md` に記録する。検査の合格だけで、モデルの振る舞いを評価済みとはしない。

| 依頼 | 主なスキル | 成果で確認すること |
| --- | --- | --- |
| iOSのプロジェクト一覧と詳細を設計する | hiro-design-app | OSとプロトタイプの区別、画面の関係、状態、主要操作 |
| 管理画面の検索と絞り込みを改善する | hiro-design-webapp | 検索結果、0件、解除、選択、キーボード、密度 |
| スキル集を紹介するサイトを作る | hiro-design-website | 具体的な見出し、実装済み内容、用途への導線、架空の実績を作らない |
| 3案の比較を要約レポートに整える | hiro-design-report | 単位・比較条件・図表・出典、架空データの明示 |
| 方針を3ページのスライドで説明する | hiro-design-slides | 筋道、各ページの主張、続きのページ、移動 |
| 既存画面をレビューする | hiro-design-review | 場所・影響・理由・修正案と優先順位、依頼範囲の尊重 |

使い分けの確認: 集客LPの依頼はWebサイト、業務用一覧はWebアプリ、長文の根拠整理はレポート、口頭発表はスライド。API内部処理やデータベースだけの変更では、デザインスキルを主たる作業手順にしない。
