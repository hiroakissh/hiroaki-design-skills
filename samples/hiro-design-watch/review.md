# 確認記録: hiro-design-watch

- 確認日: 2026-11-01（Asia/Tokyo）
- 形式: Watchの形状と状態を比較するHTMLプロトタイプ。ネイティブWatchアプリではない。
- 適用スキル: [本文](../../skills/hiro-design-watch/SKILL.md)、対象別のガイドと[出典一覧](../../docs/watch-design-guides.md)。
- 実施方法: スキルの判断をこのサンプルのHTML・CSS・JavaScriptへ手作業で反映し、生成したHTMLをブラウザで表示。生成コマンドが自然言語のスキルを自動解釈したものではない。

## 適用した判断

| 判断 | サンプルへの反映 |
| --- | --- |
| 一目の確認と短い操作 | 一つの時間と主操作を表示。長い設定画面を持ち込まない |
| 形状への適応 | 角型は縦の流れ、丸型は曲面を避けた中央配置、縦長は細い幅に合わせた文字と縦配置 |
| アプリと情報面の区別 | 「一目で確認」から「開く」で同じセッションへ戻る。特定OSのTileやcomplication実装と呼ばない |
| 低電力状態と秘匿 | 常時表示でも時刻と位置関係を保ち、作業名を「集中タイマー」、動的な値を `--:--` へ置換。操作はアウトラインの利用不可表示 |
| 色以外の意味 | 「開始できます」「集中しています」「中断しています」「おつかれさま」と主操作のラベルで区別し、単色表示でも残す |
| OSへの配色の適応 | 時計内部はAtmospheric GraphiteのDarkを使用。OLEDの黒キャンバスと単色化はこのサンプル内のデバイス適応で、15色×2の正本は変更しない |

## 実施した確認

- 幅1200 CSS pxでLight/Darkの通常表示と常時表示を表示し、全高JPEGを4枚保存。時計の内部は両方とも暗い表示。
- 幅390 CSS pxでLightのアプリ表示、Darkの常時表示・単色表示を確認。ページの横幅は390pxで、各時計の内容の縦横はみ出しもなく、主情報・操作の文字が収まることを確認。
- 25分から20分へ変更、開始、5分進行、中断、再開、完了、もう一度の操作を確認。中断中・実行中の不適切な設定操作が無効になることも確認。
- 情報面からアプリへ移動し、残り時間と実行状態が保持されることを確認。Darkでも進行中から常時表示を往復し、20分の実行中へ復帰した。
- 常時表示中、3つの時計内に元の作業名が残らず、値が `--:--` になり、時計と外側のタイマー操作が無効になることをDOMと実表示で確認。
- キーボードのEnterで丸型の開始を実行し、フォーカス枠と状態の反映を確認。サンプル一覧と紹介サイトのWatchリンクからこのサンプルへ移動できた。
- 状態遷移の自動検査で5〜60分の上限・下限、中断中の進行禁止、再開時の残り時間、完了後の非負値、情報面・常時表示でのタイマー不変、入力状態を直接変更しないことを確認。
- 配色の既存58組に加え、この黒キャンバスに載る文字・アクセント・境界・フォーカスの5組を数値検査した。

## 比較条件

初版。固定依頼文の25分・09:41・作業名と、1200px/390pxを基準にする。画像の通常表示は25分の開始前へ戻して取得。時間は自動で進まず、「5分進める」は状態比較のための操作。

## 確認していないこと

実機のpt/dp/px、OS標準部品、Crown・ベゼル・物理キー、VoiceOver/TalkBack、OS文字拡大、ハプティクス、屋外可読性、バックグラウンド実行、センサーや通信は未検証。

常時表示は設計上の概念例。実OSの更新周期やタッチ可否、点灯率、電池、焼き付き、各ストア審査への適合は検証していない。現行Wear OSなどのAmbient中の入力仕様を一律の「操作不可」と定義するものではない。MIPや低ビット画面はCSS単色表示だけでは再現できない。

資料索引の最終確認では、各資料の確認日も出力するようにした。設計判断と表示への変更はなく、最終ビルド後に通常・常時表示の4画像を再取得した。
